## How to use

For information on counter usage and configuration, refer to the [demo website](https://count.getloli.com).

## Usage

### Using Docker (Recommended)

The administration page requires three secrets. Copy the example file and
replace every placeholder before starting:

```shell
cp .env.example .env
```

For an HTTPS production deployment, set `APP_SITE` to the public origin and
configure `TRUST_PROXY` as described in
[Reverse proxy and HTTPS](#reverse-proxy-and-https). Then start the bundled
Compose service:

```shell
docker compose up -d --build
```

Both the SQLite counter database and the administrator session database are
stored under `./data`. Back up this directory and keep it mounted across
container replacements.

To run the published image directly:

```shell
docker pull ghcr.io/journey-ad/moe-counter:latest
docker run -d --name moe-counter \
  --restart unless-stopped \
  --env-file .env \
  -p 3000:3000 \
  -v "$(pwd)/data:/app/data" \
  ghcr.io/journey-ad/moe-counter:latest
```

The image runs as the unprivileged `node` user (UID/GID `1000`). Ensure a
bind-mounted `data` directory is writable by that user. For a deliberate local
plain-HTTP test, set `NODE_ENV=development` and
`SESSION_COOKIE_SECURE=false`; do not use those settings behind production
HTTPS.

After startup, open `/admin/login`. Public counter URLs remain unauthenticated,
but a Name must now be created from `/admin` before its public URL starts
counting.

### Deploying from Source

Node.js 22 and pnpm 10 are required:

```shell
git clone https://github.com/journey-ad/Moe-Counter.git
cd Moe-Counter
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env
# Replace the administrator placeholders in .env.
pnpm start
```

When developing over plain HTTP, use `NODE_ENV=development`; production should
run behind HTTPS with Secure cookies.

### Configuration

All secrets must be supplied through environment variables or an uncommitted
`.env` copied from [`.env.example`](./.env.example). The application fails at
startup if any required administrator setting is missing or invalid.

| Variable | Required | Default | Purpose |
| --- | --- | --- | --- |
| `ADMIN_USERNAME` | Yes | — | Username for the single administrator. |
| `ADMIN_PASSWORD` | Yes | — | Administrator password. Use a long random value. |
| `SESSION_SECRET` | Yes | — | Independent session-signing secret, at least 32 characters. |
| `NODE_ENV` | No | — | Use `production` to enable Secure cookies by default. |
| `APP_SITE` | No | Request origin | Canonical public origin, such as `https://counter.example.com`. |
| `APP_PORT` | No | `3000` | HTTP listening port. |
| `DB_TYPE` | No | `sqlite` | Counter store: `sqlite` or `mongodb`. |
| `DB_URL` | MongoDB only | `mongodb://127.0.0.1:27017` | MongoDB URI; include a database name in production. |
| `DB_INTERVAL` | No | `0` | Delayed counter-write interval in seconds; `0` writes immediately. |
| `SESSION_DB_PATH` | No | `data/admin-sessions.db` | SQLite file used only for administrator sessions. |
| `SESSION_COOKIE_SECURE` | No | Based on `NODE_ENV` | Explicit `true`/`false` Secure-cookie override. |
| `TRUST_PROXY` | No | `false` | Trusted proxy hop count or comma-separated addresses/CIDRs. |
| `LOG_LEVEL` | No | Application default | `debug`, `info`, `warn`, `error`, or `none`. |
| `GA_ID` | No | — | Optional Google Analytics G-Tag ID. |

`ADMIN_PASSWORD` and `SESSION_SECRET` must be different secrets. Never put
either value in Compose YAML, source control, logs, URLs, or reverse-proxy
configuration.

### Database deployment

#### SQLite

SQLite counter data always uses `data/count.db`. Administrator sessions default
to `data/admin-sessions.db`. In the container these resolve to
`/app/data/count.db` and `/app/data/admin-sessions.db`, so `/app/data` must be a
persistent writable volume:

```yaml
services:
  moe-counter:
    image: ghcr.io/journey-ad/moe-counter:latest
    volumes:
      - ./data:/app/data
```

Stop writes before copying SQLite files for backup. Copying only
`admin-sessions.db` is optional—losing it signs administrators out—but
`count.db` contains the counters and must be preserved.

#### MongoDB

Set an explicit database name and use a network-reachable host:

```dosini
DB_TYPE=mongodb
DB_URL=mongodb://mongo:27017/moe-counter
```

Inside Compose, `127.0.0.1` refers to the application container, not the
MongoDB container. Use the MongoDB service name (for example `mongo`) or an
external MongoDB hostname. Counter data lives in MongoDB, but administrator
sessions still use `SESSION_DB_PATH`; keep `/app/data` mounted even with
MongoDB. Back up MongoDB with the tools appropriate to the service.

### Reverse proxy and HTTPS

Production HTTPS should terminate at a trusted reverse proxy. Set:

```dosini
NODE_ENV=production
APP_SITE=https://counter.example.com
SESSION_COOKIE_SECURE=true
TRUST_PROXY=1
```

`TRUST_PROXY=1` is appropriate only when exactly one trusted proxy sits in
front of the application and the application port is not publicly reachable.
For other topologies, set trusted proxy addresses or CIDRs, separated by
commas. The value `true`, which would trust every proxy, is rejected.

Example Nginx location:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Do not expose the application port directly when relying on proxy-derived
HTTPS or client IP information.

### Upgrading an existing installation

1. Stop the old process and back up `data/count.db`, or take a consistent
   MongoDB backup.
2. Pull the new image or source revision.
3. Add `ADMIN_USERNAME`, `ADMIN_PASSWORD`, and a new independent
   `SESSION_SECRET` to the deployment environment. The application will not
   start without them.
4. Confirm `APP_SITE`, Secure-cookie, trusted-proxy, and persistent-volume
   settings.
5. Start the service and verify `/heart-beat`, `/admin/login`, and one existing
   counter.

No counter schema migration is required. Existing Names remain valid even when
they contain characters that new Names no longer permit. The important
behavior change is that unknown public Names now return HTTP 404 and are not
created implicitly; create new Names from the administration page first.

### Operational checks

- `GET /heart-beat` should return `200` with `alive`.
- Administration pages send `Cache-Control: no-store`.
- `GET /@:name`, `GET /get/@:name`, and `GET /record/@:name` stay public for
  existing Names.
- Back up the selected counter store regularly and protect the `.env` and
  session database from disclosure.
